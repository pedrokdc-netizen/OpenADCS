# ESP32-S3 horizon firmware (port plan)

Status: **no firmware yet**. Only the porting contract (golden vectors) exists.

## Firmware to fork
The Waveshare Thermal-45 firmware is the official **SENXORESP32S3** ESP-IDF 5.4.1 project, distributed as a
download from the Waveshare wiki *Resources* section (not a GitHub repo). Community alternatives (check licences
before forking): `Broiler747tb/ThermalCam` (licence NOASSERTION, has a LICENSE file) and
`0015/ESP32_Thermal_Camera_Viewer` (MIT). The datasheet of the MI0802 is NDA-marked: do not commit it.

## Golden vectors (`golden/`)
Generated by `python tools/make_horizon_golden.py` (deterministic; tested by `simulation/tests/test_horizon_golden.py`).

* `frames.bin` – 6 frames, little-endian `uint16`, 62 rows × 80 columns (9,920 B each), centi-kelvin.
* `horizon_golden.json` – camera geometry, per-case mount, dead pixels, prior nadir/γ, calibration table name,
  expected status / limb-point count / nadir (float64 reference), and tolerances.
* `cold_polar_az0` is a negative case (expects `TOO_FEW_POINTS`).

## Porting contract
The float32 port of `horizon_processing.estimate_nadir` must, for every case:
same status; limb-point count within `n_points_abs`; nadir within `nadir_deg` (0.02°) of the reference;
processing time under `processing_time_ms_max` (20 ms) measured on target with `esp_timer_get_time()`.
The Python float32 emulation already satisfies this (`test_float32_port_stays_inside_tolerances`).

## Budgets
* Frame: 9,920 B `uint16` (PSRAM not needed for one frame; keep 2 for double buffering).
* SPI sensor readout ≈ 10 ms at 10 MHz; UART frame transfer (fused architecture) ≈ 50 ms at 2 Mbaud → prefer
  sending limb points (~400 B).
* Output: nadir unit vector + 2×2 covariance + status, 10 Hz, to the ADCS MCU over UART.
* Measure real cycle costs and replace the timing ASSUMPTIONS in `Esp32Config`.
